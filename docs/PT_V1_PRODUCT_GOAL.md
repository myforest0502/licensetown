# LicenseTown PT版 v1.0 商品化ゴール

Last fixed: 2026-09-09
Status: **共有済みの一旦の完成ライン。今後のチャットでも勝手に広げない。**

## 1. 定義

LicenseTown PT版 v1.0 の「一旦完成」とは、

> **修正や改善は今後も続く前提だが、理学療法士国家試験受験生に商品として提供し、対価を受け取って継続利用してもらえる状態。**

完全無欠、全機能完成、将来機能の先回り実装を意味しない。

商品化判定の中心は、

> **新規ユーザーが登録し、問題を解き、履歴が保存され、弱点に応じた次の学習が提示され、途中停止・再開でき、本人が「今日何をすればいいか」を迷わず判断できる。重大なデータ破損・出題不能・学習不能がなく、実利用者による数日間の確認を通過している。**

である。

## 2. v1.0 商品化の必須条件

### A. 勉強が成立する
- Q1-Q2000 が正式接続されている。
- 出題 -> 回答 -> 保存 -> 採点 -> 解説 -> 次の問題、が安定して動く。
- 5問単位、30問学習、一時停止、再開、終了、リセットが学習履歴を壊さず動く。
- 通常学習は保存済み問題・正答・解説を使い、毎問AI生成に依存しない。

### B. 学習者ごとに次の勉強が変わる
- `question_attempts` を正式履歴として使う。
- Knowledge Node、正誤、自信度、過去履歴から、未学習・確認中・修復中・修復済み・再確認期限・定着を区別する。
- 間違えた問題は、同じ問題をただ繰り返すのではなく、同じNodeの別問題で修復確認する。
- STRONG different-Q + confidence=1 を修復確認の主要条件とする。
- Recent Cooldown と exact-repeat equivalence を尊重し、不自然な重複出題・証拠水増しを防ぐ。

### C. 誤答から定着までの本線が閉じている
正式な中核ループは、

`誤答 -> 観察可能な間違い方の分析 -> 同じNodeの別問題で修復 -> 修復確認 -> 3日 -> 7日 -> 1か月 -> 定着 / 再修復`

- 同じQの正解だけでは修復確認にしない。
- 弱い別問題だけでは強い修復確認にしない。
- 3日・7日・1か月の再確認を時間軸で扱う。
- 再確認で誤答/unknownなら新しい修復サイクルへ戻す。
- 間違い方は心理を断定せず、観察可能な証拠として分類する。
  - 自信あり誤答
  - 迷いのある誤答
  - unknown
  - 別問題でも同Nodeを誤答
  - 同じ問題を繰り返し誤答
  - 一度修復した後の再誤答
  - 単発誤答

### D. 本人が「次に何をすればいいか」分かる
- 本人画面の判断authorityを一本化する。
- 現在地、今日やること、優先課題、修復・再確認・未学習のどれを優先するかが矛盾しない。
- 学習戦略の `repair / recheck / exploration` 意図が実際の exact-Q selector まで届く。
- 正答率などの事実表示と、formalな到達度・判断を混同しない。

### E. 苦手分析が利用者の行動につながる
最低限、利用者が
- どこが弱いか
- どんな間違い方をしているか
- 修復できたか
- 次の再確認はいつか
- また崩れたか
を理解できる。

大規模な伴走カルテUIは v1.0 必須ではない。内部に `companion_record.py` 等の証拠層があり、必要な短い表示に使えることを優先する。

### F. 商品として事故らない
少なくとも次の致命的不具合がないこと。
- 出題不能
- 回答不能
- 採点/解説不能
- 学習履歴消失・破損
- pause/resume 不能
- reset で想定外データ破壊
- 同じ問題の異常連発
- 正答/解説/Q ID/Nodeの重大な不整合
- エラー発生箇所を追跡できない状態

「壊れない」だけでなく、壊れた場合に Q / Node / state / selection / event から原因を追跡できることを含む。

### G. 実利用者による受け入れ確認
- 息子さんを含む実利用で、通常の学習を数日使う。
- 特別に作った試験データではなく、普通に問題を解く中で評価する。
- 少なくとも以下が致命的に起きないことを確認する。
  - 何をすればいいか分からない
  - 同じ問題ばかり出る
  - 解説/採点がおかしい
  - 履歴が消える
  - 学習が途中で進めなくなる
  - 今日のおすすめと実際の出題が食い違う
- 発見した問題は **本線に影響するものだけ** 商品化前に直す。

## 3. v1.0 商品化前に必須ではないもの

次は「良くしたいもの」だが、商品化を止める理由にはしない。
- Phase11 の長期的・完全な統計的実証
- 3日/7日/1か月の全パターンを自然履歴で全部観測し終えること
- 完璧なAI伴走カルテ
- 豪華なダッシュボード
- 詳細な学習時間・疲労分析
- 30問内position分析のための新session linkage
- 全分野の高度な統計
- 全ユーザー向けの高度な個別最適化
- 模試分析の完成
- HP、街、アバター、居酒屋、案内所など将来構想
- 将来起きるかもしれない例外への先回り防御

これらは v1.1 以降、または実利用で必要性が確認された時に行う。

## 4. 開発判断ルール

新しい修正候補を見つけたら、まず次を判定する。

1. **今、実際に起きている問題か？**
2. **v1.0 商品化条件のどれかを壊すか？**
3. **息子さん/受験生の学習効果または継続利用に直接影響するか？**

いずれにも当てはまらなければ、今は実装せず Backlog/TODO に送る。

「あるかもしれない」「将来困るかもしれない」「安全のため念のため」だけでは v1.0 の作業に入れない。

---

## 5. 車モデルによる優先順位

v1.0 までは以下を優先する。
- **走る**：問題 -> 回答 -> 保存 -> 採点 -> 解説 -> 次へ
- **曲がる**：弱点・修復・定着に応じて次の出題が変わる
- **止まる**：pause/resume/end/reset が安全
- **壊れない**：履歴・Question Bank・Node・sessionの整合性
- **壊れた所を特定できる**：Q/Node/state/selection/eventで追跡可能
- **特定したら修復できる**：学習はrepair/retentionへ戻せる、システム不具合は再現・修正できる

枝葉の磨き込みより、**本線を安全・快適・乗り心地よく走れる車にすること**を優先する。

## 6. v1.0 完成判定

次をすべて満たした時点で、LicenseTown PT版を **v1.0 商品化完了** と判定する。

- A〜F のコード/設定/本番経路が揃っている。
- 必要な自動テストがGREEN。
- 本番相当環境で登録〜学習〜保存〜再開〜次学習まで通る。
- 数日間の実利用で、商品利用を止める重大障害がない。
- 発見した残課題が「商品化ブロッカー」か「v1.1以降」か分類されている。

ここまで到達したら、未実装の改善候補が残っていても **一旦完成** とする。

以後の作業は「完成させるための工事」ではなく、**販売後の改善・v1.1以降の開発**として扱う。
