# LicenseTown 診断充足度・試験重要度・学習戦略 v0.1

更新日: 2026-09-12
状態: 設計仕様（本番ロジック未変更）

## 1. 目的

LicenseTown の最上位目的は、ユーザーを理学療法士国家試験に合格させることである。

そのため、単純な正答率、累積問題数、Knowledge Node 到達度のどれか一つだけで学習優先順位を決めない。

本仕様では、次の4つを分離して扱う。

1. 診断充足度: その分野について得意・普通・苦手を判定できるだけの証拠があるか
2. 生の到達度: Canonical Knowledge Node の状態から算出する現状の学習到達度
3. 試験重要度: 実際の国家試験で、その分野が合否へどの程度寄与するか
4. 現在の学習優先度: 今このユーザーが次に時間を使う価値がどこにあるか

「苦手であること」と「今もっとも優先して勉強すべきこと」は同義ではない。

---

## 2. 既存 truth path は維持する

正式な学習 truth path は変更しない。

question_attempts
→ derived Knowledge Node state
→ field / strategy / readiness
→ selector
→ presentation

Knowledge Node state は既存の以下を前提とする。

- 未着手
- checking
- repairing
- repaired
- recheck_due
- stable

誤答後は、同一問題の即時反復ではなく、原則として同一 Node の別問題による repair → check → 時間を空けた recheck → stable を目指す。

本仕様はこの truth path の上に「診断充足度」「試験重要度」「分野別目標」を追加する設計であり、Knowledge Node を置き換えない。

---

## 3. 生の到達度は共通尺度のままにする

現在の Node-weighted progress は、分野横断で共通の生の到達度として保持する。

既存重み:

- unseen = 0
- repairing = 10
- checking = 30
- recheck_due = 60
- repaired = 70
- stable = 100

各分野の Canonical Knowledge Node で平均する。

重要度が低い分野だからといって、生の到達度 70% を 90% 相当などに換算して表示してはならない。

代わりに、分野別の「目標到達度」を別に持つ。

表示例:

- 到達度 70% / この分野の目標 65% / 目標達成
- 到達度 82% / この分野の目標 90% / あと少し

これにより、現在地の数値を歪めず、合格戦略上の十分条件だけを分野別に変えられる。

---

## 4. 診断充足度を追加する

### 4.1 状態

少なくとも以下を区別する。

- 未評価
- 評価中
- 暫定評価済み

暫定評価済みになった後、学習状態として別軸で以下を持つ。

- 得意
- 普通
- 苦手

将来必要なら、苦手改善後の状態として「一旦克服」「定着済み」を追加する。

### 4.2 初期診断の最小問題数

LicenseTown は 30問を1サイクルとする。

初期診断は、各18分野について最低60問 = 2サイクルを基本単位とする。

ただし、60問に到達しただけでは十分条件としない。

最低限、次も満たす必要がある。

- 可能な範囲で distinct question を使う
- 特定の少数 Node に偏らない
- Canonical Knowledge Node の十分な広がりを確保する
- 同一問題反復で問題数だけを稼がない

Node breadth の具体的な閾値は、18分野ごとの Node 数と問題供給量を監査してから確定する。現段階で一律の割合を固定しない。

### 4.3 証拠の非対称性

「苦手」と「得意」は同じ証拠量で判定しない。

複数の独立した Node で誤答が続く場合、60問未満でも repair を開始できる。

一方、少数問題で全問正解しても「得意」と確定してはならない。

理由は、少数標本の全問正解は未観測領域を保証しないためである。

したがって、弱点検出は早く、得意認定は慎重に行う。

---

## 5. 初期フェーズの「今日やること」

初期診断が不足している期間は、通常の adaptive allocation より先に、未評価分野を埋める目的を持つ。

基本方針:

1. 60問未満の分野を優先する
2. 60問以上でも Node breadth 不足なら評価中として扱う
3. 複数候補がある場合、試験重要度の高い分野を優先する
4. Safety-critical および明白な重大弱点 repair は別レーンとして割り込み可能にする

重要:

「全18分野が60問に到達するまで弱点 repair を禁止する」という意味ではない。

診断不足を減らすことを通常配分の主目的にしながら、Safety と重大弱点は並行して直す。

---

## 6. 60問到達後の暫定評価

各分野が診断条件を満たした時点で、暫定的に得意・普通・苦手を判定する。

判定材料は raw accuracy のみではなく、少なくとも以下を使う。

- 正答率
- distinct question 数
- distinct Canonical Node 数 / coverage
- 誤答 Node の分散
- repair 後の別問題正答
- spaced recheck の結果
- 問題難易度情報が信頼できる場合はその補正

現段階では「80%以上=得意」等の固定閾値を採用しない。

分野ごとの問題難易度・試験出題構成を調べずに一律閾値を置くと誤判定を起こすためである。

---

## 7. 苦手分野は30問単位で再評価する

暫定的に苦手と判定された分野は、追加30問を基本ブロックにする。

- 60 → 90問で再評価
- まだ苦手なら 90 → 120問で再評価
- 必要なら 120 → 150問で再評価

ただし、無制限に同じ戦略で追加し続けない。

連続ブロックで改善が乏しい場合は「問題数不足」ではなく「戦略不適合」の可能性を疑う。

### 7.1 停滞判定で検討するもの

- 同じ Node 群で繰り返し落としているか
- 未修復 Node が残っているか
- repair 問題の質・対応 Node が適切か
- 時間を空けた再確認で落ちているか
- 問題理解ではなく基礎知識不足か
- 特定疾患・評価・介入など小領域へ弱点が集中しているか

停滞時は、単純な +30 の継続ではなく、repair の粒度・出題内容・復習間隔などを変更する。

---

## 8. 「苦手状態」と「現在の優先度」を分離する

ある分野が苦手であり続けても、そこへ学習時間を無制限投入してはならない。

例:

精神医学が300問学習後も苦手である一方、別の高得点寄与分野がほぼ未評価なら、精神医学だけを追加し続けることは合格可能性を下げる場合がある。

したがって以下を分離する。

- weakness_state: 得意 / 普通 / 苦手 / 一旦克服 / 定着済み 等
- current_learning_priority: 今の学習時間をどこへ配るべきか

「苦手 = 常に最優先」という設計は禁止する。

---

## 9. 一旦克服と定着済み

累積正答率だけで克服判定しない。

最低限、次の流れを満たす方向で設計する。

誤答 Node
→ 別問題で repair 成功
→ checking 成功
→ 時間を空けた recheck 成功
→ 一旦克服 / stable

「一旦克服」は、その時点で学習優先度を下げてよい状態を意味する。

「定着済み」は、十分な時間間隔を置いた recheck でも維持できている状態を意味する。

---

## 10. 試験重要度 Exam Weight

### 10.1 目的

18分野を同じ重要度として扱わない。

実際の理学療法士国家試験における出題頻度・配点寄与・継続性を調べ、合格への期待値が高い分野へ学習時間を多く配る。

### 10.2 根拠データ

2026-09-12 時点で Library に第42回〜第61回の20年分、午前・午後の問題PDFが存在することを確認済み。

対象は40冊（20年 × 午前/午後）。

この20年実データを Exam Weight の一次根拠とする。

リポジトリの現行 Question Bank は Q1〜Q2000 であり、past_exam 1100問 / non-past_exam 900問の source audit があるが、Question Bank 内の件数だけをそのまま国家試験頻度とみなさない。

理由は、教材Question Bankの収録方針と実際の国家試験全問分布が同一とは限らないためである。

### 10.3 各分野で集計する項目

- 20年総問題数
- 20年総配点寄与
- 1年平均問題数
- 1年平均配点寄与
- 各年の出題数
- 出題年率
- 年ごとの分散 / 安定性
- 直近5年
- 直近10年
- 20年全体
- 実地問題等、配点差がある問題区分の比率
- 長期に対する直近の増減傾向

### 10.4 Exam Weight の原則

最終 Exam Weight は、まず「実際の得点寄与」を中心に置く。

recency や安定性は補正要素にするが、恣意的に大きくしない。

仮の直感値を本番設定へ入れてはならない。

具体式・係数は20年監査結果を見てから確定する。

---

## 11. 分野別目標を変える

Exam Weight が確定した後、18分野ごとに以下を持てる設計にする。

- target_arrival: 目標到達度
- minimum_diagnostic_questions: 初期診断の最低問題数（基準は60。変更には実データ根拠が必要）
- recheck_intensity: 再確認の強さ
- weak_additional_budget: 苦手追加学習に割く標準上限・見直し点

高頻度・高得点寄与分野:

- 高い target_arrival
- より厚い recheck
- 必要なら多めの追加学習予算

低頻度・低得点寄与分野:

- 生の到達度はそのまま表示
- 合格戦略上の十分目標は低めに設定可能
- 同じ苦手でも無制限投入を避ける

ただし Safety-critical 内容は試験頻度だけで軽視しない。

---

## 12. 最終的な学習優先度

最終的な current_learning_priority は、概念上少なくとも次を統合する。

- Exam Weight
- 現在の弱点度
- target_arrival との差
- 診断不足 / 不確実性
- retention / spaced recheck 状態
- 残り時間
- Safety priority

ただし、0〜100の任意スコア同士を無根拠に掛け算して本番投入しない。

各要素が「なぜ合格可能性を上げるのか」を説明でき、実利用データで検証できる形にする。

---

## 13. UI 契約

### 13.1 今日やること

ユーザーに対する唯一の行動命令 / ナビゲーションとする。

例:

「今日は○○を10問」

ユーザーが次に何をすべきかは、ここだけを見れば分かる状態にする。

### 13.2 学習の現在地

状態説明に限定する。

ここで別の「今日は○○を10問」を出して、今日やることと競合させない。

現在地と次の行動が内部的に異なること自体は正常である。

例: 現在地では生理学の診断不足が大きいが、Safety repair のため今日やることは病理学、など。

UI上は行動命令を一つにする。

---

## 14. 既存 PR342 との関係

現行の low-coverage exploration floor は、未学習範囲を広げる方向として維持する。

本仕様が確定するまで、感覚だけで selector の比率を再調整しない。

20年 Exam Weight、診断不足、実利用履歴を監査した後、必要な差分だけを変更する。

Safety priority は維持する。

## 15. 実装前に必須の監査

1. 第42〜61回の全問題を18分野へ信頼できる方法で分類する
2. 年・午前午後・問題番号・配点区分を保持する
3. 分類不能 / 複合領域は無理に自動確定せず監査対象へ出す
4. recent 5 / 10 / 20年を分けて集計する
5. 配点ルールの年度差を公式根拠で確認する
6. 18分野ごとの問題供給量と Canonical Node 数を確認し、60問 + Node breadth が実行可能か検証する
7. 本番 question_attempts から現在の18分野別 distinct question / distinct Node / accuracy / recheck 状態を再集計する
8. selector 変更前に shadow で新旧配分を比較する

## 17. 本仕様でまだ固定しないもの

以下は監査前に数値を決めない。

- 得意 / 普通 / 苦手の正答率閾値
- Node breadth の最低割合
- Exam Weight の計算係数
- 18分野ごとの target_arrival
- 弱点分野へ追加投入する最大問題数
- 停滞判定の正確なブロック数
- Safety 割り込みの最終配分率

固定値を先に作り、その数字にユーザーを合わせるのではなく、実際の国家試験データと学習データから決める。

---

## 18. 完成条件

この設計の完成は、単にロジックが動くことではない。

最低限、次を満たした時点を完成とする。

- 未評価分野を放置しない
- 少数正解だけで得意扱いしない
- 明白な弱点と Safety は早期 repair できる
- 一つの苦手分野へ無限に学習時間を吸われない
- 国家試験で点になりやすい分野へ相応に時間を使う
- 生の到達度を偽らない
- ユーザーには「今日何をやるか」が一つだけ示される
- selector の変更理由を実データで説明できる
- 最終判断基準が「合格可能性を上げるか」になっている
