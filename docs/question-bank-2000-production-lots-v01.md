## Production workflow

Each original lot follows the validated Batch02 line:

1. Select exact existing-Node targets plus reserved new-Node concept slots.
2. Draft more candidates than the accepted quota when needed.
3. Reject same-demand or semantic duplicate candidates before formal Q-ID allocation.
4. Stage accepted set with evidence and semantic review seals.
5. Run duplicate, category, Node, task/ability, level, Safety and strong-supply validators.
6. Allocate formal Q IDs only after staging is green.
7. Update questions / answers / explanations / question_tags / Knowledge Nodes / manifest / schema atomically.
8. Require full CI green.
9. Merge and verify Render live.
10. Recalculate remaining budget from the new formal bank before the next lot.

The final 6 past_exam questions are handled separately after the 233 original questions so original quality/repair targets are not diluted by import mechanics.
