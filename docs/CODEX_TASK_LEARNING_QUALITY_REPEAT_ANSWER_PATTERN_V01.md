# Codex 作業指示書: Learning Quality v0.1

## 最重要条件

**使用量の残数に対して途中で残数不足になるようなら開始してはならない。**

この条件を満たせない場合は、作業を開始せず、その旨だけ報告すること。

## 今回のゴール

商品として成立するところまでをゴールとする。今回の修正対象は次の2点のみ。

1. 同一Qの早すぎる再出題を止める。
2. 5問セットで正答位置が露骨に予測できる並びを防ぐ。

細かい改善点を見つけても、この2点の成立に不要ならその場で広げない。別タスク候補として記録するに留める。

## 商品成立の判定条件

### A. 同一Qの再出題
- 30問終了後、次の30問以降では、前回までの誤答を分析して同じKnowledge Nodeの類似問題・別問題を出すのは許可する。
- ただし、まったく同じQは原則として短期間に再出題しない。
- 同一Qの再出題は、既存の定着確認スケジュールである 3日後 / 7日後 / 1か月後 のタイミングで候補にする。
- 同一Qの直後再出題で修復確認を成立させない。既存の「same-Qだけではrepair confirmationにしない」「STRONG different-Qを主要条件とする」思想を維持する。
- 現行のRecent Cooldownにある Safety singleton / fallback / recheck_due 等の例外を精査し、上記ルールに反する同一Q直後再出題を止める。
- ただし、同じKnowledge Nodeの別Qは引き続き優先してよい。
- exact-repeat equivalence の evidence identity 仕様は壊さない。

### B. 5問セットの正答位置
- 問題内容や正式正答そのものは変更しない。
- 選択肢を毎回シャッフルする方式には安易に変更しない。履歴・解説・正式answer mappingとの互換性を壊さないこと。
- 5問提示時の正答位置について、自然なランダム性を残しつつ、受験者が規則を読める極端な並びを避ける。
- 毎セットA〜Eを1回ずつ必ず使う方式は禁止。最後の答えが推測可能になるため。
- 最低限、ABCDE / EDCBA のような完全連番、AAAAA等の全同一、ABABA等の露骨な反復パターン、過度な同一文字連続を候補生成時に避ける設計を検討する。
- ルールは5問セット生成側に置き、正式問題データの正答を書き換えないことを優先する。
- random / adaptive / category 等、実際に5問提示へ流れる経路で同じ品質ルールが効くか確認する。

- 最小変更を優先する。
- mainを直接変更しない。このbranch上だけで作業する。
- DB migrationは原則不要。必要だと判断した場合は実装前に止まり、理由を報告する。
- Production DBへ書き込まない。
- Phase11を本番昇格させない。
- UIレイアウトを変更しない。
- Question Bank本文・正答・解説を大量編集しない。
- unrelated cleanup / refactorをしない。

## テスト要件

少なくとも以下を追加・更新する。

### 同一Q再出題
- 直前30問に含まれる誤答Qそのものが、通常repairとして次の30問に出ない。
- Safety singletonでも、3日未満では同一Q直後再出題しないことを新仕様として確認する。
- 同Nodeに別Qがあれば、その別Qが修復候補になる。
- 3日 / 7日 / 1か月の既存retention horizonを壊さない。
- exact-repeat equivalenceを壊さない。

### 正答位置
- 5問の正答並びがABCDE / EDCBA / AAAAA / ABABA等の禁止パターンにならない。
- 過度な同一文字連続を防ぐ。
- ただし毎回A〜E各1回にはならず、自然な偏り（例 AABCD など許容ケース）が残る。
- 問題IDや正式正答データ自体は変更しない。

関連テストと全体テストを可能な範囲で実行し、結果を記録する。

- 残っている非blockerの改善候補（あれば短く）
- 「商品として成立」の判定

商品として成立すると判断したら、細部の追加改善を始めず一旦終了すること。
